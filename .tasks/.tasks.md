It is now `rows + registries === findings`: the typed total against two lists a person edits. A verdict added without a re-take is red in 20 milliseconds from a suite rather than 22 seconds into the gate — which is the first time anything in this chain could catch that without running ESLint.

  **`TRIAGED_RULES` moved to `lib/triaged-rules.ts` because the derivation needed it, and that closed the older suggestion on the way.** It was an array in `scripts/check-eslint-gate.ts` pairing a rule id — a string somebody typed — with a registry's `findingsByFile()`. Nothing checked the pairing, so a registry attached to the wrong rule would have read as a complete reading of a rule it had never looked at, and the gate would have printed it green. Both registries export their own `RULE` and the list is built from it; a case holds each entry's `registry` path to a file that declares that id, and another holds the module to spelling no rule id at all.
