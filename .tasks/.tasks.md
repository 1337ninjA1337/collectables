## A toast that nothing can dismiss, bounded at both ends (2026-09-17)

- [DONE: 2026-09-17] [est: 16000] **The hold had no ceiling and the queue had no depth** — `<ToastView>`'s effect opened `if (held) return;`, so a held toast scheduled NO timer at all. That is correct while a pointer really is resting on the toast and wrong the moment the `onHoverOut` never arrives: a drag that ends over the overlay, a window that loses focus mid-hover, a phone reporting a stuck hover. `held` stays true with nobody there and a `zIndex: 9999` banner sits over the top of every screen for the rest of the session. The queue had the matching hole — `show()` appended, and the only thing that ever removed an entry was that entry's own dismissal timer, which a held toast does not have.

  **The fix is two pure functions, which is the other half of the task.** `nextToastDeadline({ held, hasAction, elapsedMs })` in `lib/toast-timing.ts` and `capToastStack` in `lib/toast-stack.ts`. Both rules used to be lines inside a React module that `tsx --test` cannot import, so the four cases covering them matched the effect's SOURCE — a `return`, a dep array, the name of a ref — which is green on a cleanup that never runs and on a ceiling off by a factor of a thousand. Fourteen cases call them now, and the two render cases that asserted `timers.live()` was EMPTY on hover assert the ceiling instead, which is the behaviour that changed.

  **Held life is capped at four windows from when the toast appeared; a release still restarts the full window.** So the worst case is ceiling + window rather than the ceiling exactly, and that is the trade on purpose: the failure being fixed is UNBOUNDED life, and a release is a real signal from a real pointer — the one thing a stuck hover never sends. `elapsedMs` comes from a `shownAt` ref captured once, not recomputed per re-run, or every hover would reset the ceiling and the bug would survive its own fix.

  **The stack keeps three and drops the OLDEST.** The direction is the whole decision: the newest toast describes what just happened and is the only one whose action the user is still reaching for. A list that already fits is returned by identity rather than copied — a fresh array on every `show()` would re-render the stack, restart the entrance animations, and reset the very timers the cap exists to bound.
