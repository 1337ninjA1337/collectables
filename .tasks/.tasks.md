## The list the action commits, read when the action fires (2026-09-10)

<!-- First bullet of "Row-props follow-ups" (2026-09-10), raised three times before that in "Keyboard-reorder follow-ups", "Item-reorder follow-ups" and "Reorder-extraction follow-ups". -->

- [DONE: 2026-09-10] [est: 16000] **`rows` may be a function, and both screens now pass one** — the action props are built during the render that DREW the row, and the action fires later: a screen reader focuses a card, the user thinks, then presses. A cloud merge or a `loadMore` in between changes the list, and a handler closing over the old array commits an order nobody is looking at — `reorderItemsInCollection` and `reorderOwnedCollections` both renumber from the list they are handed, so it is a silent corruption of the manual order rather than a visible mistake. The web drag shim solved exactly this with a `latest` ref, four commits before anything else in this thread; the keyboard route never had one.

  **Availability stays a render-time question and the MOVE stops being one.** The platform needs the action list when it draws the row, so `accessibilityActions` is still computed from the render's list. What changed is that the handler re-resolves the rows and re-asks `availableReorderActions` against the fresh ones: a row drawn in the middle of a five-item list and re-fired against a two-item one is now last, and "move down" would have clamped — a write that changes nothing, announced as a move.

  **The announced total is the new length too**, and the pick-up's, which is the half that would have been wrong in the quietest way: "moved to position 3 of 5" spoken over a list of two.

  **`ownedCollections` moved above the home screen's `!ready` early return** and became a `useMemo`, because a ref is a hook and a hook may not sit below a conditional return. That also fixes the re-derivation flagged two commits ago: `collections.filter(...)` was running on every render and handing every card a new array.

  **A plain array is still accepted.** Building a ref to say "this list cannot change" would be ceremony, and every case in the suite passes arrays. 5 new cases in `__tests__/reorder-actions.test.ts` — the fresh commit, the move the list grew out of, the render-time offer that must not go empty, the pick-up's length, and both call shapes. Six pins across three screen suites re-anchored on the getter and on the ref being declared above the early return. `npm run verify` green: 7993 tests, 20/20 guards, bundle 10.1 KiB under budget. No DB migration, no creds.
